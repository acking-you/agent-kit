# Rust engineering guide

Apply to Rust you write or review. A project's own lint configuration and established conventions take precedence.

## Crates and dependency graph

- Split crates by role and give each role a dependency budget: `*-types`/`*-protocol` hold data, serde and validation only (no runtime, I/O or transport error types); `*-core`/`*-runtime` hold logic and traits without an executor; `*-client`/`*-sdk`/`*-adapter` own runtime and transport; one binary package is the composition root that owns `main`, the global allocator, build stamping and the production feature set.
- Keep the internal graph strictly downward. When a small crate needs one item from a large one, move that item down instead of adding the edge; break cycles with a trait or an inert-until-installed hook in the lower crate that the composition root wires.
- Split a crate to isolate rebuilds, compile in parallel, break a cycle or spare a small consumer heavy dependencies, not because it is long. Re-export moved items at their old paths so callers don't churn. Inside a large crate default to `pub(crate)` and enable `unreachable_pub`.
- Centralize versions in `[workspace.dependencies]` and lints in `[workspace.lints]` with `[lints] workspace = true` in every member; comment every workspace-level `allow` with its cause and removal condition.
- Libraries depend on siblings with `default-features = false` and only forward features; heavy integrations sit behind `dep:` optional features; the binary selects production features. Remember feature unification: a trimmed list does nothing if anything in the graph enables more.
- Confine a second major version of a shared dependency to one crate, private, exposing only your own types.
- Put cross-crate test helpers behind a never-default `test-support` feature enabled from `[dev-dependencies]`; `cfg(test)` does not cross crates.
- Stamp volatile build inputs (git hash) only in the binary's `build.rs` and pass them to libraries at runtime, so libraries don't rebuild on every commit.
- Route each cross-cutting policy (process spawning, HTTP client and TLS, home directory, path canonicalization) through one wrapper and ban the raw API with clippy `disallowed-methods`: the `reason` names the replacement, the wrapper holds the only `allow`, every other exemption states its reason inline.

## Types and zero-cost abstractions

- IDs and validated values are newtypes with private fields; `new`, `FromStr`, `TryFrom` and `Deserialize` (`#[serde(try_from = "...")]`) all go through one validating constructor, and struct fields use the newtype. For many same-shaped IDs use one `Id<Marker>` with `PhantomData<fn() -> Marker>`.
- Use `NonZero*` for limits and divisors, build constants in const context, and keep the type through downstream APIs instead of re-checking zero.
- Author traits with associated types and `async fn`/`-> impl Future<Output = _> + Send` for static dispatch; when a registry needs heterogeneity, add one object-safe twin trait with a blanket impl and erase only there. Closed sets are enums, open registries and test seams are `dyn`, closures are generic parameters unless stored. Reserve `#[async_trait]` for the erased trait.
- Share immutable fan-out data as `Arc<str>`/`Arc<[T]>`, never `Arc<String>`/`Arc<Vec<T>>`; box rarely used large enum variants; serialize through a borrowed mirror type instead of cloning into an owned message.
- Don't build data just to inspect it: validate JSON with `IgnoredAny`, peek a tag with `&RawValue`, measure output with a counting `io::Write`, and return `Cow` from transforms that usually change nothing, behind a cheap pre-check.
- In per-frame and per-item hot paths: reuse owned scratch buffers via `clear()`/`mem::take`; key caches on every input that affects output and normalize the rest; keep size-independent results apart from size-dependent ones; resume incremental state instead of reprocessing growing input; cap input-proportional work with benchmark-backed limits.
- For large internal indexes, intern strings into an arena with `u32` IDs, size `SmallVec` to a measured common case, use fast hashers only for keys an attacker cannot choose, and convert lengths with `try_from`, never truncating `as`.
- Assert relations between constants at compile time with `const _: () = assert!(cond, "why");`, including hand-written lists against `EnumCount`. Enums stored in atomics or on disk get `#[repr(u8)]` with explicit discriminants; small fixed lookups are `const` slices scanned linearly.
- Mark guards and state-transition results `#[must_use = "consequence"]`; model exactly-once work as consuming methods (`finish(self)`/`abandon(self)`) plus a `Drop` that logs if neither ran.
- Use `#[inline]` only on tiny non-generic functions called across crates; ship with thin LTO and `codegen-units = 1` in a dedicated release profile instead of `inline(always)`.
- Choose serde strictness by source: `deny_unknown_fields` within one build; `#[serde(other)] Unknown` and `#[serde(default)]` across versions, keeping internal matches exhaustive (`#[non_exhaustive]` is not wire tolerance); keep and warn on unknown user-config keys (`#[serde(flatten)]` extra map) so saving never drops them; lenient parsing for model output; tagged over `untagged` where variants could be spoofed.

## Errors

- Libraries and API seams return `thiserror` enums whose variants carry what callers branch on (path, pid, elapsed, retry-after) plus `#[source]`; `anyhow` belongs to binaries, top-level glue and tests. Never flatten a cause into text (`anyhow!("{e}")`, `Result<_, String>`).
- Classify on the error with exhaustive matches (`is_retryable()`, no `_` arm) and map to an explicit decision enum at the retry site; classify `anyhow` errors with `downcast_ref` on typed markers, never by message text.
- Keep the machine-readable kind, the message for the user or model, and the debug cause in separate fields.
- Errors crossing a process boundary are serializable data with stable string kinds; unknown kinds decode to `Other`; convert `io::Error` explicitly at the boundary, not through a blanket `From`.

## Async, cancellation and resources

- Every `.await` is a cancellation point: restore state changed before it with a `Drop` guard, not with code after it. Only cancel-safe futures go in `select!` (`biased;`, cancel branch first); move non-cancel-safe reads into a task feeding a channel.
- Sub-scopes get `child_token()`; cancel on early return with `drop_guard()`, since dropping a token does not cancel it. Own tasks with `JoinSet`/`TaskTracker`. A timed-out `spawn_blocking` is abandoned, not cancelled: batch blocking work into one call and pass it a token.
- Never hold a sync lock across `.await`: expose locked state through `with_x(|g| ..)` closures with sync return types, document lock order, collect under the lock and act outside it. Async mutexes only for deliberate single-flight; `ArcSwap` for read-mostly config; comment each `Acquire`/`Release` pairing.
- Bound every queue and decide what happens when it is full; treat `broadcast` lag as a resync; give debounce a maximum wait; prefer `watch` over `Notify` for state.
- Compute one deadline per operation and pass it to nested retries so timers never stack; cap and jitter retries, honor `Retry-After`, never retry deterministic failures.
- Spawn children through one API: own process group (job object on Windows), registered with a session-scoped killer that lives outside the worker, killed as a group (`kill_on_drop` leaks grandchildren), parent-death signal where available, non-interactive environment and null stdin. Cover spawn-to-handoff with an armed guard disarmed synchronously on success.
- Resource guards expose a consuming `close(self) -> Result`; `Drop` is best-effort, logs, works without a runtime and never blocks the executor. Cleanup that must finish at shutdown runs on a dedicated thread, not `spawn_blocking`, whose queued tasks are dropped.
- Shut down in order: restore user-visible state, cancel, join within a summed budget, reap children, flush telemetry, with a hard-exit watchdog.
- Write files through one atomic helper: unique temp in the same directory opened with `create_new` and final permissions, write, `sync_all`, `rename`, remove the temp on failure. Preserve line endings when editing a file.
- With `panic = "abort"`, `Drop` and `catch_unwind` do nothing: restore the terminal and kill children in the panic hook, report SIGABRT, run third-party parsers of untrusted input in a child process, and avoid APIs that panic at runtime (`block_in_place` on a current-thread runtime or in a `LocalSet`).
- Instrument with `#[instrument(skip_all, fields(..))]` and stable dotted names, never hold an entered span across `.await`, record errors as fields (`error = %e`), give secret types a redacting `Debug`, and scrub at every telemetry exit.

## Safety, lints and panics

- Deny `clippy::indexing_slicing` in shipped code and set `allow-indexing-slicing-in-tests` in `clippy.toml`; use `get`, `split_at_checked`, `split_first`, slice patterns and `floor_char_boundary`, and never mask a miss with a default (`unwrap_or("")`) that hides a bug. Where a panic loses user state, add `#![cfg_attr(not(test), deny(clippy::unwrap_used, clippy::expect_used, clippy::panic))]`.
- Production panics state the invariant: `expect("why this cannot fail")`, `unreachable!("what guards this")`. For survivable can't-happen cases, `debug_assert!(false, "...")` and return a fallback.
- Suppress lints only with `#[expect(lint, reason = "...")]` at the narrowest scope; never crate-wide `allow(dead_code, unused_*)`.
- One unsafe operation per block, each with `// SAFETY:` naming the precondition, enforced by `clippy::undocumented_unsafe_blocks`; justify every `unsafe impl Send/Sync`. FFI lives in per-OS `imp` modules behind a safe API with a no-op fallback; `#![forbid(unsafe_code)]` where none is needed; prefer `nix`/`rustix` to raw `libc`; never `transmute` types whose layout you don't control.
- Never mutate the process environment once threads exist; make resolvers pure functions of injected values. Tests that must mutate env use an RAII guard plus `#[serial(KEY)]`, or a one-test integration binary for `OnceLock`-cached state.
- On Windows targets canonicalize with `dunce` and resolve home through one helper.

## Tests

- Small suites inline; large ones in `#[cfg(test)] #[path = "x_tests.rs"] mod tests;` sibling files; black-box behavior in `tests/`. Share fakes from a test-support crate with its own tests. Name tests as behavioral claims.
- Use paused tokio time and injectable clocks instead of sleeps; gate slow end-to-end tests with `#[ignore = "how to run"]`.
- Reach for heavy techniques only where they pay: `loom` for lock and atomic protocols behind a test-only feature guarded by `compile_error!`; differential tests against the old implementation or non-streaming path when rewriting; `cargo fuzz` for parsers of untrusted input; heap-counting soak tests for leak-prone lifecycles; benchmarks for hot-path caps.
