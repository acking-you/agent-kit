# Rust engineering guide

Apply to Rust you write, change or review. The project's lints, conventions, edition and `rust-version` win. Change crate layout, manifests or lint configuration only when the task calls for it. A bullet that starts with a context (`Workspace:`, `Library:`, `CLIs:`) applies only there.

## Crates and dependencies

- Workspace: dependencies point one way. To reach one item in a large crate, or to share a type between two components, move it into a lower crate both use instead of adding an edge. Break a would-be cycle with a trait in the lower crate that the binary implements and passes in; use a `OnceLock` hook set at startup, a no-op while unset, only when passing it down is impractical.
- Workspace: a bin-only package that nothing depends on owns `main`, `#[global_allocator]` and feature selection; libraries only forward features. Stamp the git hash only in its `build.rs` and pass it to libraries at startup, so they don't rebuild per commit.
- Split a crate to cut rebuilds, parallelize the build or break a cycle, never for length; spare small consumers heavy dependencies with a split or an optional `dep:` feature. Re-export moved items at their old paths so callers compile unchanged, and update tracing filters, whose targets follow the module path.
- Data and wire-type crates take no async runtime, HTTP client or I/O dependency: convert transport errors into owned data at the boundary, and check with `cargo tree -e normal -p <crate>`.
- Workspace: declare each dependency once in `[workspace.dependencies]` with minimal features, and `default-features = false` if any member needs defaults off; edition 2024 rejects a member-level opt-out, and member features only add. Set `resolver = "3"` in the root `[workspace]` and `[lints] workspace = true` in every member. After adding dependencies run `cargo tree -d`; keep an unavoidable second major version inside one crate.
- Workspace: share test helpers behind a non-default `test-support` feature (`#[cfg(any(test, feature = "test-support"))]`) that dependents enable in `[dev-dependencies]`; a dependency's `#[cfg(test)]` code is never built for your tests.
- Library: default to private or `pub(crate)` under `#![warn(unreachable_pub)]`, and keep dependency types out of public signatures unless they are deliberately part of your API.

## Types and zero-cost abstractions

- Ids and constrained values that cross an API, wire or storage boundary get a newtype with a private field and one fallible constructor, decoded via `#[derive(Deserialize)] #[serde(try_from = "Raw")]`, never a plain derive or `#[serde(transparent)]`. Use `NonZero<T>` for values that must be nonzero.
- Dispatch statically by default: closed sets are enums; `dyn` is for open registries, stored heterogeneous callbacks and test seams. Write async trait methods as `fn op(&self) -> impl Future<Output = T> + Send`, not `#[async_trait]`; where a registry needs `dyn`, add a boxed-future twin trait with a blanket impl and erase only there.
- Let the compiler flag new cases: no `_` arm where each variant of your own enum needs a decision; destructure `let Self { a, b, c: _ } = self;` in hand-written `PartialEq`, `Hash`, merge or serialization code; generate parallel enum tables and `ALL` lists from one declaration (strum or `macro_rules!`); relate constants with `const _: () = assert!(A > B, "why");`.
- Tag-only type parameters use `PhantomData<fn() -> T>`. Hand-write `Clone` on generic `Arc`-backed handles; the derive adds a `T: Clone` bound. Put `#[must_use = "why"]` on guards, builders and outcomes, and bind guards to `_guard`, never `let _ =`, which drops at once.
- Never narrow with `as` when the value can exceed the target: use `T::try_from` with an explicit reject or saturate policy, and `checked_*`/`saturating_*` for lengths, budgets and caller-supplied `Instant`/`Duration` math. On the wire, durations are integers named with their unit (`timeout_ms`).
- Make observable order deterministic: `BTreeMap`/`IndexMap` or sort before output, files, hashes and snapshots; end comparators with a unique tie-break (`total_cmp` for floats). Never persist `DefaultHasher` output; hash explicit bytes with a named algorithm.
- Keep decisions and state transitions pure: take `now`, randomness and env values as arguments and return an outcome enum, leaving I/O to a thin loop. When tests must control env or time, add an explicit constructor (`from_lookup`, `with_clock`) that the ambient one calls.
- Share immutable data cloned to many owners as `Arc<str>`/`Arc<[T]>`/`Bytes`, not `Arc<String>`/`Arc<Vec<T>>` unless it must grow. Return `Cow<'_, str>` from transforms that usually change nothing, behind a cheap pre-check such as a static `RegexSet`.
- On hot or large JSON paths, don't build a `serde_json::Value` to validate, peek or measure: use `from_str::<IgnoredAny>`, borrowed structs with `&RawValue` fields, or `to_writer` into a byte-counting `io::Write`.
- In per-frame or per-item loops, reuse buffers (`clear()`, or `mem::take` and restore) and compare borrowed forms (`a.as_deref() == b`) instead of allocating. Parse streaming input incrementally from resumable state, not the whole buffer per chunk. Key caches on exactly the inputs that change the result, and cap input size and time on latency-sensitive threads. Reserve `#[inline]` for small non-generic cross-crate functions on hot paths.
- Where `rust-version` allows, use `std::sync::LazyLock`/`OnceLock`, not `lazy_static`/`once_cell`.

## Errors

- Return a `thiserror` enum from APIs whose callers branch on failures or that other crates consume; use `anyhow` with `.context()` in binaries, tests and glue. Variants carry what the caller acts on (path, id, retry-after) and keep the cause in a `#[source]`/`#[from]` field that the `#[error(..)]` text does not repeat.
- Never flatten a cause into text (`anyhow!("…: {e}")`, `e.to_string()`, `Result<_, String>`) except once at a serialization boundary. Branch on types, not message text: `downcast_ref` for the outermost error, `e.chain().find_map(|c| c.downcast_ref::<T>())` for a nested one. Log `anyhow` errors as `{e:#}` and others as tracing `error = ?e`; `{e}` and `%e` drop the chain.
- Classify on the error type: `is_retryable()` matching every variant, or one pure `classify(&err, attempt)` returning a decision enum for the retry loop. Retry only idempotent operations, with capped jittered backoff or a capped `Retry-After`, through one retry crate such as `backon`.
- Errors that cross a process or network boundary get their own serializable type with a stable snake_case tag per kind, converted explicitly (no blanket `From`). Users, clients and LLMs get a kind and an actionable message; the cause chain stays in logs.

## Async and concurrency

- A future can be dropped at any `.await` (timeout, `select!`, abort) and `?` returns early: restore, re-queue or decrement state in a `Drop` guard created before that point, not in code after it. Cover multi-step acquisition with a `#[must_use]` guard that undoes it, disarmed after success with no `.await` before the handoff.
- In `select!` loops, race only cancel-safe futures: use a codec stream (`FramedRead`), poll one pinned future by `&mut`, or move `read_line`, `read_exact` and `write_all` into a task feeding a channel. Loops that must stop promptly use `biased;` with the cancellation branch first.
- Dropping a `CancellationToken` does not cancel it: give spawned work a `child_token()` and keep `child.clone().drop_guard()` until the work reaches its owner, so an early `?` cancels it. Own tasks in a `JoinSet` (aborts on drop) or a `TaskTracker` (only waits; pair it with a token).
- Run blocking work (`std::fs`, synchronous clients, CPU-heavy loops) as one `spawn_blocking` per batch, never nested, checking a cancel flag: it can't be aborted, and a `timeout` only stops waiting. Avoid `block_in_place`; it panics on a current-thread runtime, the `#[tokio::test]` default.
- Use `tokio::sync::Mutex` only when a guard must live across `.await`; never hold a std or `parking_lot` guard across one. Copy what you need and drop the guard before sending, calling back, doing I/O or re-entering the same `DashMap`. Document lock order on types with several locks.
- Default to bounded channels and decide what full means (wait, drop or fail); justify each unbounded one. Treat `broadcast` `Lagged` as data loss and resync. Wait for state with `watch` (`wait_for`), not check-then-`Notify`.
- Compute one deadline per operation and pass it down (`timeout_at`); nested retries and waits use the remaining budget. Shut down in order within a time bound: restore user-visible state, cancel, join with a timeout, flush.
- When adding `#[instrument]`, write `#[instrument(skip_all, fields(id = %id))]`; the bare form formats every argument. Never hold `span.enter()` across `.await`; use `.instrument(span)`. Give types holding secrets a redacting `Debug`.

## Processes, files and environment

- Spawn supervised non-interactive children through one wrapper (such as `process-wrap`) that gives each its own process group (Unix `process_group(0)`, Windows a Job Object), and kill the whole group on cleanup; `kill_on_drop` reaches only the direct child. Use `Stdio::null()` stdin and disable prompts and pagers (`GIT_TERMINAL_PROMPT=0`, `GIT_PAGER=cat`, `PAGER=cat`). Interactive children such as `$EDITOR` stay in the foreground group.
- `Drop` cleanup is best-effort, synchronous, non-blocking and works without a runtime; blocking cleanup goes to a plain `std::thread`, not `spawn_blocking`, whose queued tasks are dropped at shutdown. Resources whose release can fail also offer `close(self) -> Result`.
- Write state files through one helper: `NamedTempFile::new_in(dir)`, write, `sync_all`, `persist` (`persist_noclobber` to create only), plus a directory fsync on Unix when the rename must survive a crash. When replacing a user's file, copy its permissions (the temp is 0600), keep its line endings and BOM, and refuse non-UTF-8 content instead of `from_utf8_lossy`.
- Don't mutate the process environment once threads exist: read env once into config and test through an injected lookup. A test that must set real env is the only test in its own `tests/*.rs` binary.
- With `panic = "abort"`, `Drop` and `catch_unwind` don't run on panic, and unwinding tests hide it: restore the terminal and kill child groups in a panic hook that chains the previous one. If the host must survive a dependency panicking or hanging on untrusted input, run that work in a child process with a timeout.
- CLIs: write through `writeln!` on a locked stdout and exit quietly on `BrokenPipe`; `println!` panics when the reader closes the pipe.
- Windows: canonicalize with `dunce::canonicalize`; `std` returns `\\?\` paths that break other tools and path equality.

## Serde and wire formats

- Pick strictness by source: `deny_unknown_fields` for same-version internal messages; ignore-and-warn (`serde_ignored`) for user config; a `#[serde(flatten)] extra` map to keep unknown keys when rewriting a file other versions write; lenient coercion only for LLM or hand-typed input. Prefer tagged enums to `untagged`, which silently takes the first variant that parses.
- For data other versions read or write, add fields as `#[serde(default)]` and give enums a catch-all instead of failing the message: `#[serde(other)] Unknown` for string and internally tagged enums, or a last `#[serde(untagged)] Unknown(serde_json::Value)` to keep the payload (it also absorbs malformed known variants). `#[non_exhaustive]` is for published APIs, not wire tolerance.

## Lints, panics and unsafe

- When a wrapper must replace a raw API (spawning, HTTP client setup, home directory), ban the raw API with clippy `disallowed-methods` whose `reason` names the wrapper, and mark the wrapper and each real exception `#[expect(clippy::disallowed_methods, reason = "..")]`. Clippy reads only the nearest `clippy.toml`.
- Where a panic is costly (services, TUIs, agents), don't index or slice: use `get`, `split_first`, `split_at_checked`, `let [a, b] = s else {..}` or iterators, enforced by `clippy::indexing_slicing` with `allow-indexing-slicing-in-tests = true`. When a miss means a bug, return an error rather than `.get(..).unwrap_or(default)`. Cut a `str` to a byte budget at `floor_char_boundary(n)`, never at `n`.
- `Drop`, teardown and supervision code must not panic; enforce it there with `#![cfg_attr(not(test), deny(clippy::unwrap_used, clippy::expect_used, clippy::panic))]`. Elsewhere, production `expect`/`unreachable!` messages state the invariant that rules failure out, and failures that can happen return errors. Where a panic is worse than degrading, `debug_assert!(false, "..")` and fall back.
- Silence lints with `#[expect(lint, reason = "..")]` on the narrowest item, or `#[allow(lint, reason = "..")]` when the lint fires only in some builds; never a bare `#[allow]` or crate-level `allow(dead_code, unused_*)`.
- Every `unsafe` block and `unsafe impl` gets a `// SAFETY:` comment naming the precondition (`clippy::undocumented_unsafe_blocks`), one unsafe operation per block. Put `#![forbid(unsafe_code)]` in the root of crates that need none. Never `transmute` between `repr(Rust)` types; equal size is not equal layout.

## Tests

- Test time-dependent code with an injected clock or `#[tokio::test(start_paused = true)]` plus `tokio::time::advance` (tokio `test-util`), never real sleeps. Pin a wire format other versions depend on with one test against a hand-written `json!` literal.
- When rewriting or adding an incremental or streaming path, assert identical output against the old or full implementation. A parser you write for untrusted bytes gets a `cargo fuzz` target. Write `#[ignore = "why; how to run"]`, never a bare `#[ignore]`.
