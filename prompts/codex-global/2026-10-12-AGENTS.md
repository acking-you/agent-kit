## TSearch Production SSH

- Run every TSearch SSH hop and remote command inside one persistent `zellij` session: create or reuse it first, and leave it attachable. Run local macOS work directly, not in `zellij`.
- Log in with `/Users/boliu/tools/login.sh --no-kitty <env-file>`. It opens the jump-host shell and copies the real instance's SSH command to the clipboard; run that command inside the jump-host shell, not locally. Never judge the instance (e.g., engine processes) from the jump host.
- The clipboard command contains credentials: never print, log, or reproduce it, and suppress echo when pasting it into the remote TTY.
- On the instance, stay read-only unless the user explicitly authorizes a mutation.

## Long-Running Tasks

- For long waits, avoid prolonged foreground sleeping or polling. Reuse or create one heartbeat for the current task (about every 5 minutes unless the user or task says otherwise), then yield.
- Keep durable state in a task checkpoint and linked files: job/session IDs, logs, evidence, remaining steps, acceptance criteria, authorization boundaries. Update it before yielding; read it before acting on each heartbeat.
- The heartbeat prompt is a replaceable current-stage brief, not a log: objective and stage, next concrete action, checkpoint path, and essential constraints. Rewrite it when the stage, blocker, next action or relevant constraints change. Replace obsolete details; never append task history. Leave unchanged prompts alone. Keep full constraints and progress in the checkpoint; compaction must not widen permissions.
- When a prerequisite finishes, continue already-authorized dependent work through verification and delivery; a passing build or exited helper is not completion.
- Stay quiet on unchanged checks; notify on meaningful progress, failure, required user action, or completion. Once the whole task is done, pause and verify only the matching automation. Preserve attachable remote sessions and unrelated automations.
